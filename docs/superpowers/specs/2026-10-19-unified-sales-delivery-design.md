# 米面粮油店统一销售开单与配送需求设计

日期：2026-10-19

状态：需求已确认，待实施（2026-10-20 补充导出与旧数据范围）

适用范围：当前粮油进销存项目的销售、库存、配送和销售统计

## 1. 背景与目标

门店同时经营零售和批发，销售由店员手动录入，暂不建设扫码收银台或支付对接。订单可能由客户自提，也可能由门店配送。零售客户不一定有档案，因此开单时必须能快速选择老客户、新增客户或使用散客。零售与批发共用一个开单入口和一份订单台账。

用户提供的纸质样张是窄幅“粮油配送中心销售清单”，主要内容为店名、客户、录单时间、单据编号、商品名称、单位、数量、单价、金额、本单应收、经手人、电话、地址。系统须支持预览、打印和下载 PDF，版式接近样张。

**核心业务规则：需要配送的订单，在确认送达前不正式扣减账面库存，也不计入已完成销售；确认订单后占用可售数量，防止重复销售。** 自提订单在确认交付时一次性完成销售和库存扣减。录入订单本身不产生库存出库流水。

本设计取代 `docs/superpowers/specs/2026-10-11-sales-list-export-design.md` 中“保存销售清单立即扣减库存”的规则。该旧稿中的纸质清单字段及 PDF、Excel 导出诉求均在本期范围；与本文件冲突时，以本文件为准。

## 2. 现状与缺口

| 项目现状 | 对新流程的影响 |
| --- | --- |
| 销售页面复用采购式明细表单，保存时要求 `customerId` | 散客不能直接开单，客户新增需离开订单 |
| 客户下拉能按名称、编码搜索；客户创建要求手填编码 | 不能按手机号快速找老客户，也不适合开单时快捷建档 |
| `SaleOutService.create` 保存单据后立即按 FIFO 扣库存，修改/删除会回滚旧出库 | 不能表达待配送、配送中和送达后出账 |
| `inv_stock` 有总量、锁定量、可用量；当前销售过程没有订单占用关系 | 可以扩展占用逻辑，但须记录占用来源并保持汇总一致 |
| 统计从销售单和明细直接聚合 | 待配送订单会被提前计入销售，必须限定完成状态和完成日期 |
| 已有商品、客户、单位、仓库资料和批次库存 | 可复用主数据、单位换算及 FIFO 扣减能力 |
| 未发现配送任务、打印模板、销售单客户/商品快照 | 需要新增配送记录、打印资料和历史快照 |

## 3. 范围与业务定义

### 3.1 本期范围

1. 一个“销售开单”菜单：创建、编辑、查询零售或批发订单，支持自提或配送。
2. 一个“销售订单”列表：按订单类型、交付方式、客户、单号、状态、日期筛选，查看详情及可执行操作。首页可提供“快速开单”入口，指向同一页面。
3. 选择老客户、快捷新增客户、散客开单；订单保存客户和商品资料快照。
4. 订单确认后的库存占用、自提交付、配送中、送达确认、取消及退回处理。
5. 配送清单打印预览、PDF 下载、窄幅模板、重复打印，以及销售清单 PDF、Excel 导出。
6. 库存、订单列表和销售统计按新状态展示正确口径；本期不处理旧销售订单，后续重新制作测试数据。
7. 新增操作权限、操作记录和相应验证。

### 3.2 本期边界

- 不建设 POS、扫码收银、线上支付、自动生成应收应付账款、电子签名、司机定位、路线规划。
- 不实现一单多车次配送或部分送达。本期一单一次交付，结果是整单送达或整单退回；如数量不符，先退回，复制原单建立新单并调整数量后重新配送。已正式完成的订单不得通过编辑或删除改变库存，后续用销售退货单处理。
- 单价继续由店员手动输入，不在本期建设零售/批发自动价目表。“本单应收”表示订单金额，不等同于已收款或真实应收账款余额。
- 普通自提订单也采用手动录单，不要求客户档案；批发如需长期按客户查询或未来对账，使用正式客户档案。

### 3.3 两个独立维度

| 维度 | 取值 | 决定什么 |
| --- | --- | --- |
| `saleType` 销售类型 | 零售、批发 | 列表筛选、订单展示和后续价格策略扩展；本期不自动改价 |
| `fulfillmentType` 交付方式 | 自提、配送 | 必填的收货信息、打印入口和完成流程 |

零售也可以配送，批发也可以自提；不能将“批发”直接等同于“配送”。

## 4. 使用角色与统一入口

销售管理菜单下设置“销售开单”和“销售订单”两个可见入口；旧“销售出库”菜单改名或重定向到“销售订单”，避免出现两套业务记录。销售订单详情可以跳转库存流水，配送订单可以打印清单。客户管理保留作完整资料维护；开单页内只显示开单所需的最少字段。

开单页从上至下展示：

1. 类型和交付方式：零售/批发，自提/配送；默认值可记住该账号上次选择，但必须清楚显示。
2. 客户：可搜索老客户；同一区域提供“新增客户”和“散客”操作。选老客户后显示联系人、电话、地址，允许本单修改。
3. 配送：仅在选择配送时展示收货人、电话、地址、计划送达时间、配送备注；收货人、电话、地址必填。
4. 商品明细：商品、业务单位、数量、单价、金额、备注；沿用基础单位换算，显示当前可售量和本单所需基础数量。
5. 合计和操作：金额实时预览；提供“保存草稿”“确认订单”。确认后进入自提交付或配送流程。

表单错误定位到具体字段或明细行。保存成功后留在订单详情，能直接打印配送清单或继续处理交付；新增客户成功后返回原表单，不丢失已填明细。

## 5. 客户处理

### 5.1 选择老客户

- 可用客户名称、手机号、客户编码搜索启用中的客户，结果显示名称、电话及地址摘要，避免同名误选。
- 选中后将客户名称、联系人、电话、地址带入本单，用户可以只修改本次配送信息；修改本单不会覆盖客户档案。
- 若需要更换客户，先提示本单已修改的收货信息将被重新带入，避免静默丢失。
- 历史订单即使客户停用或改名，也以订单快照展示和打印。

### 5.2 快捷新增客户

- 在开单页弹出轻量窗口，只要求“客户名称”；电话、联系人、地址按实际情况填写。若当前订单需要配送，缺失的收货人、电话、地址仍需在订单配送区补齐。
- 客户编码由后端自动生成且保证唯一；完整的税号、银行资料留在“客户管理”补录。快捷新增成功后自动选中该客户。
- 输入电话或名称时提示可能重复的老客户，允许用户返回选老客户；服务端仍按正式客户档案规则校验。
- 只有具备新增客户权限的人员能快捷建档；无权限时仍可选老客户或使用散客。

### 5.3 散客开单

- 散客订单不创建客户档案，`customerId` 允许为空，订单保存客户名称/收货人/电话/地址快照。自提散客默认名称为“散客”，可不填姓名电话。
- 配送散客必须填收货人、电话和地址。散客也可以录入一个本次使用的客户称呼，不自动建档。
- 客户排行将散客汇总为“散客”，不能把各个散客订单关联成同一正式客户；客户筛选提供“散客”条件。
- 本期已保存订单不自动转为正式客户。如需长期追踪该客户，在开单时使用快捷新增。

## 6. 订单与配送生命周期

使用明确的订单状态，由交付方式约束合法流转；不能让现有通用数字 `status` 同时表示客户、配送、库存和销售是否完成。状态代码固定为 `draft`、`pending_handoff`、`pending_delivery`、`in_delivery`、`awaiting_return`、`completed`、`cancelled`、`returned`。

| 阶段 | 可执行操作 | 库存变化 | 已完成销售统计 |
| --- | --- | --- | --- |
| 草稿 | 编辑、删除、确认订单 | 无占用、无出库 | 不计入 |
| 待交付（自提）/待配送（配送） | 修改前先撤销原占用并重新校验，取消，配送清单预览/打印 | 占用可售数量；总库存不变 | 不计入 |
| 配送中 | 确认送达、登记未送达并等待退回 | 继续占用；总库存不变 | 不计入 |
| 待退回 | 记录异常原因、确认货物回店 | 继续占用；总库存不变 | 不计入 |
| 已完成 | 查看、重打、走后续退货流程 | 一次性扣减总库存及占用量，生成批次扣减和库存流水 | 按完成时间计入 |
| 已取消/已退回 | 查看；可复制为新订单并调整 | 释放占用；无出库流水 | 不计入 |

确认订单时检查并占用全部明细的可售基础数量；库存不足则整个确认失败，订单保持草稿。自提使用“确认交付”完成；配送先“开始配送”，由有权限的店员在收到送达确认后点击“确认送达”。两者调用同一出库服务，以 FIFO 扣批次、写库存流水和完成时间；一个订单只能成功出库一次。

配送未送达时，先标记“待退回”，保留占用；货实际回到门店并经人确认后才标记“已退回”并释放占用。未交给配送员的订单可以直接取消并释放占用。打印和重打不改变库存或状态。已完成订单不可删除、直接改数量或撤销出库；纠错须走后续销售退货/更正业务，不能删除原始流水。未完成订单修改金额或明细时，旧占用释放与新占用校验在同一事务中进行；失败时保留原订单和原占用。

本期整单交付：确认送达时默认实际送达量等于订单量。若现场少送、拒收或换货，不点“确认送达”，记录异常并退回；复制原单调整后再次配送。后续若真实业务频繁部分送达，再扩展为多次配送单和逐行实送数量。

## 7. 库存与统计口径

所有业务数量统一换算成商品基础单位。确认订单时记录每行 `baseQty` 快照，增加 `lockedQty`、减少 `availableQty`，`totalQty` 保持不变，并保存订单级占用记录。必须维持 `totalQty = availableQty + lockedQty`；占用、取消、退回、完成须与订单状态在同一数据库事务中提交。配送中货品可能已离开仓库，因此库存页另显示“配送中占用量”；账面总库存仍按用户要求在确认送达时正式减少。店员判断能否再卖只看**可售量**，不得把配送中的占用量再次分配给其他订单。

完成时只扣一次：从 `totalQty` 和 `lockedQty` 同时扣除本单占用量，`availableQty` 不再重复扣；同时按当前有效批次 FIFO 扣减 `remainQty`，写销售批次扣减记录和销售出库流水。由于本期占用按商品汇总而非提前锁定具体批次，完成前须重新检查批次数量与汇总数量一致；若校验失败，整笔回滚并保持订单未完成，提示管理员核查。现有库存流水的 `afterQty` 取可用量，完成配送时可用量保持不变；页面应同时展示总量、锁定量和可用量，不能把 `afterQty` 误解为出库后的总量。并发确认订单、采购、盘点和完成配送继续使用仓库锁保护。

销售统计只计入“已完成”订单，按实际完成日期统计销售金额与数量；待交付、待配送、配送中另作“待完成订单金额/数量”指标，不能与已完成销售相加冒充营业额。订单列表的业务日期表示录单日期，另展示完成日期。采购统计逻辑不受此规则影响。客户排行中的正式客户按客户 ID 聚合，散客归为单独分类。库存价值和批次仍按正式扣减后的数量计算。

## 8. 配送清单与打印

已确认的自提及配送订单均可按旧稿字段导出销售清单 PDF 和 Excel；草稿不可导出。配送订单另有本节定义的配送凭证预览、打印与 PDF 下载。导出和打印都必须校验订单查看权限及各自的操作权限。Excel 包含抬头、客户、录单时间、单号、商品明细、经手人、联系方式、地址及本单应收，使用保存时快照和后端金额。

### 8.1 模板字段

打印模板以用户提供的窄幅清单为基准：

| 位置 | 内容 |
| --- | --- |
| 抬头 | 店铺名称，例如“粮油配送中心销售清单” |
| 抬头下 | 客户称呼、录单时间、订单编号 |
| 明细 | 商品名称/规格、单位、数量、单价、金额、明细备注 |
| 尾部 | 本单应收合计、经手人、联系电话、配送地址、配送备注 |
| 状态 | 待配送/配送中/已完成标识及打印时间；已完成可显示实际送达时间 |
| 签收 | 收货人签字、实际收货日期空白线，供纸面签收使用 |

仅已确认的配送订单可打印清单，草稿不能作为送货凭证。打印内容读取订单快照与后端计算金额，不读取当前客户、商品名称覆盖历史内容。长商品名换行、金额右对齐、多页时重复表头并标注页码；不同打印次数的业务数据一致。商品行超过单页时不截断。清单打印是配送凭证，不是法定发票或已收款证明。

### 8.2 输出和设备

订单详情提供“打印预览”“打印”“下载 PDF”。预览采用独立打印页面，支持浏览器打印；PDF 用于留档与重打，并保证中文字体正常显示。纸型设为可配置模板，默认先做 A5 和窄幅自定义纸型两种预设；上线前按门店真实打印机、纸张宽高、页边距和连续纸走纸效果校准。照片无法准确测出纸张尺寸，不能据此硬编码毫米值。打印与导出均需校验查看订单及打印权限，记录操作人、请求时间和模板版本；浏览器无法可靠证明纸张已实际印出，因此记录的是打印请求。

## 9. 数据与接口设计边界

继续复用现有 `biz_sale_out` 和 `biz_sale_out_item` 作为统一订单与明细，不建立零售/批发两套重复销售表。建议新增：

| 数据 | 必要字段或用途 |
| --- | --- |
| 订单主表 | `sale_type`、`fulfillment_type`、`order_status`、`customer_id` 可空、客户/收货人/电话/地址快照、录单时间、计划送达时间、实际完成时间、经手人、备注、总金额 |
| 订单明细 | 商品名称、规格、单位名称、业务数量、基础数量、单价、金额的保存时快照 |
| 订单占用表 | 订单、明细、仓库、商品、基础单位占用量、状态；支持释放与幂等检查 |
| 配送记录/操作日志 | 开始配送、送达确认、异常、退回、取消的操作人、时间、原因；保存打印请求历史 |

接口沿用 `/api/v1/sale-outs` 的查询、详情与订单创建能力，但语义从“创建即出库”改为“创建草稿/确认订单/确认完成”。新增的动作接口应独立表达确认、开始配送、送达、取消、退回和打印，服务端校验状态流转，不信任前端传入的状态、金额或可售量。订单号继续复用现有单号，前端展示为“订单编号”，本期不要求改成图片中的编号规则。

客户搜索接口增加手机号条件和联系信息摘要；新增“快捷建档”能力可复用客户创建服务，但编码由后端生成。新增权限建议为 `sale:order:confirm`、`sale:delivery:start`、`sale:delivery:complete`、`sale:delivery:return`、`sale:order:print`、`sale:order:export`；客户快捷创建仍要求 `basic:customer:create`。每个新接口必须进入权限种子和后端授权映射，前端按钮按权限显示。打印与导出接口均不得绕开订单查看授权。

## 10. 旧数据与兼容（2026-10-20 范围调整）

**本期不迁移旧销售订单，不回填旧订单的客户或商品快照，也不承诺旧单在新页面可用。** 后续重新制作一套测试数据。升级前检查是否存在旧销售数据；存在时停止升级并提示人工处理，不自动删除或重算。今后若需要保留历史订单，应另行设计状态和快照迁移，并核对库存、批次和统计。旧客户端的创建接口也随本期切换为“保存草稿”语义。

## 11. 验收场景

1. 从唯一“销售开单”入口建立零售自提散客单，不创建客户档案；保存草稿不占库存，确认订单后占用，确认交付后只出库一次。
2. 批发配送单输入手机号找到老客户，自动带出联系人和地址；只修改本单地址后，客户档案不变，清单显示本单地址。
3. 在已填三行商品的表单中快捷新增客户，返回后明细未丢失，新客户自动选中，客户编码由系统生成；发现同手机号老客户时提示选择。
4. 配送单确认后 `totalQty` 不变、`lockedQty` 增加、`availableQty` 减少；第二笔订单超过剩余可售量时无法确认。
5. 打印待配送清单不会改变库存；清单的客户、商品、数量、价格、合计和地址与订单快照一致，中文可读且多行不截断。
6. 配送中订单不进入已完成销售统计；确认送达后库存总量、锁定量和批次各减一次，有一组出库流水，按完成日期进入销售统计；重复点击完成不能再次扣减。
7. 配送失败且货尚未回店时保持占用；确认退回后释放占用，无正式出库流水，也不计入已完成销售。
8. 无客户新增权限不能快捷建档；无送达确认权限不能完成配送；无打印权限不能通过直接调用接口下载清单。
9. 已完成的新订单无法通过编辑或删除回滚库存；升级检测到旧销售订单时停止并提示人工处理，不自动修改旧数据。
10. 打印样张在目标打印机上校验纸宽、边距、换页、签收区和连续纸走纸，并由门店确认版式。

## 12. 交付顺序

1. 先完成订单状态、旧数据阻断检查和库存占用/完成的后端规则，验证并发与幂等；旧订单迁移留待后续。
2. 再改统一开单、散客、老客户搜索与快捷新增，保证手动录单流程顺畅。
3. 接着实现配送操作、清单预览/PDF 和纸张校准。
4. 最后修正销售统计与权限，并按第 11 节场景做端到端验收。
