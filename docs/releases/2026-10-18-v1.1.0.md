依据：`docs/superpowers/specs/2026-10-11-basic-data-and-statistics-design.md` 及对应实施计划。
本版本接续 `release/basic-data-business-closure-20261017` 中断时的成果，在实际项目目录完成开发与核验。

## 模块与验收边界

| 模块 | 本版本行为 |
| --- | --- |
| 基础资料 | 商品、分类、单位、单位换算、仓库、供应商、客户共七个菜单，提供查询、详情、新增、编辑、逻辑删除、启停用、选项、真实 Excel 导出 |
| 分类 | 树形维护、同级/子级新增、禁止循环父子关系、父级停用影响下级可选性、按分类筛选业务数据 |
| 换算 | 商品维度的有向换算关系；校验正倍率、循环与不一致路径；单据保存基础数量快照 |
| 采购与销售 | 真实主数据选择、名称回显、可用单位、服务端重算金额、完整新增/修改/删除与库存联动 |
| 库存 | 汇总、批次、流水查询与导出；盘点调整同步批次和流水；业务引用限制删除 |
| 统计 | 经营总览、趋势、销售商品、采购商品、库存结构、客户排行、供应商排行、分类占比，支持筛选、图表切换、表格和导出 |
| 权限 | 后端执行资源操作权限，导出独立授权；前端操作按钮按权限显示；升级补齐权限菜单种子 |

库存批次、流水和统计是业务结果，新增或修正必须通过采购、销售、撤销或库存调整产生，不能提供任意改写结果的 CRUD。用户、角色沿用现有维护功能；菜单权限页维护既定资源的授权关系。

## 基础资料接口索引

基础路径 `/api/v1/basic`，统一响应为 `ApiResponse{code,message,data}`，分页为 `data{list,total}`。

| 菜单 | 资源路径 | 权限资源名 |
| --- | --- | --- |
| 商品 | `/products` | `product` |
| 商品分类 | `/categories` | `category` |
| 单位 | `/units` | `unit` |
| 商品单位换算 | `/unit-converts` | `unit-convert` |
| 仓库 | `/warehouses` | `warehouse` |
| 供应商 | `/suppliers` | `supplier` |
| 客户 | `/customers` | `customer` |

以上每个资源均提供：

| 方法 | 后缀 | 操作权限 |
| --- | --- | --- |
| GET | 空 | `basic:{资源名}:list` |
| GET | `/{id}` | `basic:{资源名}:view` |
| POST | 空 | `basic:{资源名}:create` |
| PUT | `/{id}` | `basic:{资源名}:update` |
| DELETE | `/{id}` | `basic:{资源名}:delete` |
| PATCH | `/{id}/status` | `basic:{资源名}:status` |
| GET | `/options` | 对应列表权限或消费基础资料的业务权限 |
| GET | `/export` | `basic:{资源名}:export` |

额外提供 `GET /categories/tree` 和 `GET /products/{id}/units`。选项默认排除停用和已删除资料，历史业务仍能显示停用资料名称。导出为 `.xlsx`，按查询条件导出全部匹配记录，忽略页码限制。实际字段、请求体和完整接口模型见启动后的 `/doc.html` 中“基础资料（Basic）”与“统计（Statistics）”分组。

## 业务规则

- 业务引用、库存或换算关系存在时，禁止删除相应主数据；使用停用保留历史。
- 数据库唯一索引保留已逻辑删除资料的编码、同父级分类名称、商品换算组合；新增时请使用未占用编码，停用是已使用资料的常规退出方式。
- 采购、销售保留业务数量和单价，库存统一使用商品基础单位；金额由后端按数量和单价计算。基础数量最多四位小数，不能精确表示时拒绝保存。
- 销售按批次 FIFO 扣减，库存不足整笔失败；并发写入通过数据库事务和仓库锁串行保护。
- 单据修改保留单据 ID 和单号，先撤销旧库存影响再应用新数据；任何失败整体回滚。已有下游消耗时，采购撤销受批次可恢复性限制。
- 撤销使用保存的数量快照和批次扣减记录，不随主数据后续停用或换算倍率修改而改变。
- 库存金额按剩余批次数量乘基础单位成本估算；统计库存结构为当前库存，日期筛选不代表历史时点重建。

## 数据库部署

本次开发默认保留已有业务数据，未对开发库执行升级或初始化。上线前停止业务写入并备份数据库；MySQL DDL 可能隐式提交，不能靠事务整体撤销结构升级。

现有库先检查同父级分类重名（包含逻辑删除资料，因为唯一约束保留其名称）：

```sql
SELECT parent_id, category_name, COUNT(*) AS duplicate_count
FROM grain_oil_ims.base_product_category
GROUP BY parent_id, category_name
HAVING COUNT(*) > 1;
```

结果必须为空；如有记录，先核实引用并调整名称，不能直接删除业务资料。然后从仓库根目录执行：

```bash
bash scripts/upgrade-v1.1.0.sh --user=<升级账号> --password
```

该入口在一个 mysql 批次中执行旧逻辑删除字段对齐、单位与换算通用字段、业务基础数量快照、分类唯一约束和权限种子，遇到 SQL 错误立即停止，支持重复执行。可使用 mysql 的 `--login-path` 提供连接配置。不要在其后重复执行非幂等的单独快照补丁。快照回填按旧版真实库存行为使用历史 `qty`，不能使用今天的换算率重算历史库存。

空库才执行以下初始化，随后执行同一个升级入口安装权限菜单：

```bash
mysql --user=<初始化账号> --password < sql/grain_oil_ims_init.sql
bash scripts/upgrade-v1.1.0.sh --user=<升级账号> --password
```

脚本使用固定库名 `grain_oil_ims` 和 mysql 客户端的 `DELIMITER`，请从项目根目录运行。其他库名需要先审阅全部脚本中的 `USE`。如任一步骤失败，停止部署并修复原因后重新执行，确认结构和权限后再部署后端、前端。

升级不会扩大普通角色的既有授权。管理员需为角色分配相应菜单与操作权限，前端编辑需要详情及修改权限；修改资料时改变状态还需独立启停权限。升级和授权后退出并重新登录，以刷新 JWT 中的权限。

## 闭环验收步骤

1. 建立“袋”“箱”单位、粮食分类、大米商品（基础单位：袋）、仓库、供应商、客户，配置大米 `1 箱 = 10 袋`。
2. 采购 `2 箱 × 100 元`，预期金额 200 元，库存和批次 20 袋，入库流水 +20。
3. 销售 `3 袋 × 15 元`，预期销售额 45 元，库存 17 袋，剩余库存估值 170 元；商品、客户、供应商统计应能查到对应名称与金额。
4. 尝试销售超过可用库存，预期整笔失败，单据、批次、库存和流水不产生部分更新。
5. 修改销售数量并观察相应反向流水和新扣减；尝试撤销已被消耗的采购，预期受引用与库存一致性规则保护。
6. 修改换算倍率并停用商品，确认历史名称可回显、新单不可选择；先撤销销售，再撤销采购，按原快照恢复并归零。
7. 为只读账号验证可查询、不可新增/修改/删除；未授权导出返回 403，未登录返回 401。使用有导出权限的账号检查文件记录与筛选条件一致。

## 自动验证与限制

最终验证结果记录在 `docs/superpowers/plans/2026-10-17-business-closure-progress.md`。后端业务集成测试使用隔离 H2 的 MySQL 模式执行真实 Mapper SQL，不写开发库。

本轮最终结果：后端 `mvn package` 148 项测试通过并生成可执行 JAR；前端 10 套件、55 项测试、lint、生产构建通过。构建保留 ECharts/vendor 两项包体积提示。代码交叉审查发现的字段长度及权限契约问题均已修复；当前分支及未提交改动保留，未发布。

本机 MySQL 9.0.1 在创建临时隔离数据目录时发生原生进程崩溃（SIGSEGV），因此本次未完成真实 MySQL 的升级演练；H2 通过不能替代目标 MySQL 的迁移验收。部署前需在目标版本 MySQL 的备份副本上验证升级、重复执行和业务抽样。浏览器人工联调及已有数据库的数据质量验收仍需在运行环境完成。
