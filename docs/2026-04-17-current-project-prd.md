## 2. 项目背景

### 2.1 当前业务痛点

米面粮油门店在日常经营中同时面对采购入库、销售出库、库存变动、金额统计、权限控制等多个环节。若这些环节依赖手工登记、分散台账或多个独立工具，容易出现以下问题：

- 货物进出记录与库存数量不同步
- 采购金额、销售金额与库存变动无法一一追溯
- 操作人员权限边界不清，容易出现越权改数
- 统计口径分散，日报/月报难以快速产出
- 删除、修改单据后，库存和金额影响难以回溯

### 2.2 为什么要做这个系统

本系统用于将门店经营中的“货、单、金额、权限、统计”纳入同一套系统，形成可追溯的业务闭环。系统应同时满足：

- 门店日常业务操作效率
- 管理者的经营统计需要
- 记账员的金额核对需要
- 后续扩展独立账务模块的演进需要

### 2.3 现有方式存在的问题

- 只记录采购/销售金额但不映射库存，会造成账实不一致
- 只做库存不做金额汇总，会导致经营统计缺口
- 没有标准接口文档和 PRD，会影响开发、联调、测试一致性
- 业务单据修改或删除后的库存回滚逻辑复杂，若无明确规则易出错

### 2.4 本次建设范围和价值

本次文档建设基于当前项目代码，输出可直接用于开发和联调的 PRD 与 API 文档，核心价值是：

- 明确当前已实现的系统边界
- 明确后续目标设计，尤其是独立账务扩展方向
- 让前后端、测试、产品对业务对象、接口、错误场景形成统一认知

## 3. 产品目标

### 3.1 业务目标

- 支持采购入库、销售出库、库存汇总、库存批次、库存流水、经营统计的业务闭环。
- 支持管理员和记账员按角色完成各自职责。
- 支持以采购总金额、销售总金额、统计汇总实现基础记账与对账能力。
- 为后续独立账务模块扩展预留接口和领域边界。

### 3.2 管理目标

- 管理员可统一管理用户、角色、权限和菜单。
- 管理层可按日、月、客户、供应商、分类查看经营统计。
- 关键库存和单据修改必须可追踪。

### 3.3 数据目标

- 采购单、销售单、库存汇总、库存批次、库存流水之间建立明确关系。
- 所有金额类字段在业务单据与统计层保持统一口径。
- 分页、返回结构、鉴权方式保持全局一致。

### 3.4 质量目标

- 接口文档可直接用于前后端联调。
- PRD 可直接支撑开发任务拆解与测试用例设计。
- 关键异常场景必须有明确处理策略。
- 文档明确区分“代码现状”和“目标增强”。

## 4. 用户角色与职责

### 4.1 管理员

- 角色职责：
  - 管理用户、角色、权限、菜单
  - 查看全部采购、销售、库存、统计数据
  - 执行库存修正、删除业务单据等高风险操作
- 可访问模块：
  - 认证登录
  - 用户与角色管理
  - 采购、销售、库存、统计全部模块
- 禁止操作范围：
  - 无系统级禁止项，但高风险操作应受审计约束
- 与其他角色边界：
  - 管理员负责系统配置和权限治理
  - 不应将所有日常记账与录单职责都依赖管理员

### 4.2 记账员

- 角色职责：
  - 新增、修改、查询采购入库单
  - 新增、修改、查询销售出库单
  - 查询库存、批次、流水和统计
  - 根据采购/销售金额做基础核对
- 可访问模块：
  - 登录认证
  - 采购、销售、库存查询、统计查询
- 禁止操作范围：
  - 不负责角色权限配置
  - 不应直接修改系统级角色和菜单
- 与其他角色边界：
  - 记账员关注业务数据处理与金额核对
  - 管理员负责账号治理和高权限操作

## 6. 业务对象 / 数据实体

### 6.1 商品 `base_product`

- 业务含义：门店经营的商品主数据，作为采购、销售、库存的共同基础
- 核心字段：
  - `id`
  - `productCode`
  - `productName`
  - `categoryId`
  - `brandName`
  - `spec`
  - `baseUnitId`
  - `status`
- 与其他实体关系：
  - 与采购明细、销售明细、库存汇总、库存批次、库存流水均有关联
- 生命周期说明：
  - 创建后长期存在，可被停用，不应直接物理删除影响历史业务

### 6.2 采购入库单 `biz_purchase_in`

- 业务含义：记录一次采购入库业务的单头信息
- 核心字段：
  - `id`
  - `orderNo`
  - `warehouseId`
  - `supplierId`
  - `bizDate`
  - `totalAmount`
  - `status`
  - `remark`
- 与其他实体关系：
  - 一对多关联采购入库明细
  - 影响库存汇总、库存批次、库存流水
- 生命周期说明：
  - 新建
  - 生效
  - 可修改
  - 可逻辑删除
  - 被后续销售消耗后删除/回滚会受限

### 6.3 采购入库明细 `biz_purchase_in_item`

- 业务含义：采购单中的商品明细
- 核心字段：
  - `purchaseInId`

  - `unitId`
  - `qty`
  - `unitPrice`
  - `amount`
  - `batchNo`
  - `inboundTime`
- 与其他实体关系：
  - 对应库存批次
  - 对应库存流水中的业务明细
- 生命周期说明：
  - 随采购单创建与回滚

### 6.4 销售出库单 `biz_sale_out`

- 业务含义：记录一次销售出库业务的单头信息
- 核心字段：
  - `id`
  - `orderNo`
  - `warehouseId`
  - `customerId`
  - `bizDate`
  - `totalAmount`
  - `status`
  - `remark`
- 与其他实体关系：
  - 一对多关联销售明细
  - 影响库存汇总与库存流水
- 生命周期说明：
  - 新建
  - 生效
  - 可修改
  - 可逻辑删除

### 6.5 销售出库明细 `biz_sale_out_item`

- 业务含义：销售单中的商品明细
- 核心字段：
  - `saleOutId`
  - `productId`
  - `unitId`
  - `qty`
  - `unitPrice`
  - `amount`
- 与其他实体关系：
  - 通过 FIFO 规则消耗库存批次
- 生命周期说明：
  - 随销售单创建与回滚

### 6.6 库存汇总 `inv_stock`

- 业务含义：商品在仓库维度的汇总库存
- 核心字段：
  - `warehouseId`
  - `productId`
  - `totalQty`
  - `lockedQty`
  - `availableQty`
- 与其他实体关系：
  - 被采购、销售、库存修正影响
- 生命周期说明：
  - 可创建、更新、逻辑删除

### 6.7 库存批次 `inv_batch`

- 业务含义：采购入库形成的批次记录，用于 FIFO 扣减
- 核心字段：
  - `warehouseId`
  - `productId`
  - `sourceType`
  - `sourceId`
  - `batchNo`
  - `inboundTime`
  - `unitPrice`
  - `initQty`
  - `remainQty`
  - `status`
- 与其他实体关系：
  - 来自采购明细
  - 被销售出库消耗
- 生命周期说明：
  - 新建后逐步减少剩余数量，直至耗尽

### 6.8 库存流水 `inv_stock_flow`

- 业务含义：记录库存变化的明细流水
- 核心字段：
  - `warehouseId`
  - `productId`
  - `batchId`
  - `flowType`
  - `bizType`
  - `bizId`
  - `bizItemId`
  - `changeQty`
  - `afterQty`
  - `bizTime`
- 与其他实体关系：
  - 关联采购单、销售单、库存调整
- 生命周期说明：
  - 作为审计型流水追加写入，不应被随意更改

### 6.9 用户与权限实体

- `SysUser`：系统用户
- `SysRole`：角色定义
- `SysPermission`：权限定义
- `SysUserRole`：用户角色绑定
- `SysRolePermission`：角色权限绑定
- `SysUserPermission`：用户直接授权

### 6.10 独立账务扩展实体（目标设计）

- 代码现状：当前未实现
- 目标设计建议：
  - 账务总账 `finance_ledger`
  - 收支分录 `finance_entry`
  - 应收应付台账 `finance_ar_ap`

  - 供应商和客户可映射应付/应收

## 7. 业务流程

### 7.1 主成功流程：采购入库到库存生效

- 前置条件：
  - 用户已登录
  - 用户具备 `purchase:order:create` 权限
  - 商品、仓库、供应商基础数据有效
- 触发条件：
  - 记账员或管理员提交采购入库单
- 步骤串联：
  1. 用户填写仓库、供应商、业务日期、备注和明细
  2. 系统校验采购单请求字段和明细字段
  3. 系统创建采购单主表和明细
  4. 系统为每条采购明细创建或更新库存汇总
  5. 系统创建库存批次
  6. 系统写入库存流水
  7. 采购单 `totalAmount` 成为采购支出汇总基础数据
  8. 后续统计模块可按供应商、分类、日期聚合采购金额和数量
- 关键决策点：
  - 明细是否完整
  - 批次号是否符合业务要求
  - 库存回滚是否允许
- 结果：
  - 单据创建成功
  - 库存增加
  - 批次可被后续销售使用
- 后置影响：
  - 统计结果可感知该采购记录
  - 后续若销售消耗该批次，删除或回滚采购单会受限

### 7.2 主成功流程：销售出库到库存扣减

- 前置条件：
  - 用户已登录
  - 用户具备 `sale:order:create` 权限
  - 对应商品存在可用库存
- 触发条件：
  - 记账员或管理员提交销售出库单
- 步骤串联：
  1. 用户填写仓库、客户、业务日期、备注和明细
  2. 系统校验字段完整性与库存可用性
  3. 系统创建销售单主表和明细
  4. 系统按 FIFO 策略扣减库存批次
  5. 系统更新库存汇总
  6. 系统写入库存流水
  7. 销售单 `totalAmount` 成为销售收入汇总基础数据
  8. 统计模块可按客户、分类、日期聚合销售金额和数量
- 关键决策点：
  - 当前库存是否充足
  - 旧单回滚是否成功
- 结果：
  - 单据创建成功
  - 库存减少
  - 销售金额进入统计口径
- 后置影响：
  - 被占用批次剩余数量减少
  - 后续删除或修改销售单需要先回滚旧影响

### 7.3 异常流程：库存不足

- 前置条件：
  - 用户提交销售单
- 触发条件：
  - 明细数量大于可用库存
- 步骤串联：
  1. 系统检查库存汇总和批次
  2. 发现可用库存不足
  3. 系统拒绝创建或更新销售单
- 结果：
  - 返回 `400 insufficient-stock`
- 后置影响：
  - 单据不生效
  - 库存不变

### 7.4 回滚/撤销流程：修改采购或销售单

- 前置条件：
  - 对应单据存在
  - 用户具备修改权限
- 触发条件：
  - 用户提交修改请求
- 步骤串联：
  1. 系统查找旧单据
  2. 系统尝试回滚旧库存影响
  3. 如果回滚成功，按新请求重新创建单据影响
  4. 如果回滚失败，终止操作并返回错误
- 关键决策点：
  - 旧单是否存在
  - 旧库存影响是否已被后续业务消耗
- 结果：
  - 成功则新数据生效
  - 失败则返回冲突错误
- 后置影响：
  - 保证库存与单据一致性

### 7.5 状态变化流程：库存修正

- 前置条件：
  - 管理员具备 `inventory:stock:update` 权限
- 触发条件：
  - 管理员发现盘点差异后执行库存修正
- 步骤串联：
  1. 读取库存汇总
  2. 提交新的 `totalQty` 和 `availableQty`
  3. 更新库存汇总
  4. 写入调整型库存流水
- 结果：
  - 库存数量被修正
- 后置影响：
  - 后续统计和业务出入库都会基于修正后数量继续执行

### 7.6 全链路流程：登录到经营统计

1. 用户登录获取 JWT
2. 前端根据菜单和权限展示可访问模块
3. 记账员录入采购单或销售单
4. 系统同步更新库存和流水
5. 管理员或记账员查询统计结果
6. 若出现异常，管理员可进行库存修正或单据调整

## 9. 业务规则

### 9.1 校验规则

- 登录接口必须校验用户名和密码非空
- 采购/销售新增和修改必须校验仓库、业务日期、明细必填
- 明细必须校验商品、单位、数量、单价、金额
- 采购明细必须校验批次号与入库时间
- 库存修正必须校验 `totalQty` 和 `availableQty`

### 9.2 数量/金额规则

- 销售数量不得大于可用库存
- 金额字段统一使用 decimal 口径
- 采购单和销售单总金额应与明细金额总和保持一致
- 库存批次剩余数量不能为负数

### 9.3 唯一性规则

- 用户名必须唯一
- 角色编码必须唯一
- 批次号在业务侧应满足可追溯性要求

### 9.4 权限规则

- 所有非认证接口默认要求登录
- 用户管理、角色管理、菜单查询需基于 RBAC 控制
- 采购、销售、库存、统计接口按权限点控制

### 9.5 时序规则

- 修改单据前必须先回滚旧影响，再写入新影响
- 删除已被后续业务消耗的采购单可能失败
- 销售出库必须在库存充足前提下执行

### 9.6 约束条件

- 统一分页参数为 `pageNum/pageSize`
- 统一返回结构为 `ApiResponse`
- 统一分页响应结构为 `PageResponse`
- 当前未发现统一排序参数，文档中需明确说明

## 10. 异常与边界处理

### 10.1 参数异常

- 缺少用户名、密码、仓库、客户、供应商、业务日期、数量、金额等字段时返回 `400`

### 10.2 业务冲突

- 库存不足返回 `insufficient-stock`
- 已被消耗的采购单回滚失败返回 `purchase-in-already-consumed`
- 库存回滚冲突返回 `inventory-rollback-conflict`

### 10.3 权限不足

- 当前控制器文档层声明权限点，实际无权限场景由安全层控制

### 10.4 数据不存在

- 用户、角色、采购单、销售单、库存不存在时返回 `404` 类业务错误码

### 10.5 重复提交

- 当前代码未显式提供幂等键机制
- 对新增接口需在前端和网关层考虑重复提交防护

### 10.6 并发冲突

- 单据修改和删除涉及库存回滚，存在并发冲突风险
- 库存扣减存在高并发下库存一致性风险，当前文档需提示开发关注事务与锁策略

### 10.7 回滚失败

- 修改或删除采购/销售单时，若库存无法正确回滚，应立即失败并保留原状态

### 10.8 外部系统失败

- 当前未发现第三方系统依赖
- 后续若接 ERP / 财务系统，需补充分布式一致性与失败补偿策略

### 11.4 安全要求
