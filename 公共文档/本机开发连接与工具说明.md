## MCP 接入状态与使用方式

本次会话没有暴露用于 MySQL、Redis、Nacos 或 Docker 的专用 MCP 工具。项目中未发现 `.mcp.json`，也不存在项目级 `.codex` 目录；未核验 IDE 全局 MCP 设置，因此不能断言本机没有安装这些 MCP 服务。

连接文档让 Agent 知道应查什么；真正通过 MCP 操作，还需要宿主环境配置并启用对应 MCP 服务，将工具暴露给当前会话。本文没有安装 MCP 服务或修改 IDEA、Codex 的全局配置。

后续开发按以下顺序执行：

1. 读取本文，确认本次任务需要访问的服务，以及当前 profile 和运行环境覆盖项。
2. 检查当前会话实际提供的 MCP 工具，确认工具连接的 host、数据库、Redis DB、Nacos namespace / group 或 Docker context 与本项目一致。
3. 有合适的 MCP 工具时先进行只读连接检查。没有时明确说明工具缺失，并在现有授权范围内使用本机命令；不能仅凭文档就声称 MCP 已接入。
4. 数据库以结构与必要查询为主，避免输出整表业务数据；Redis 查询限定任务涉及的键，不使用 `KEYS *` 扫描共享实例。
5. 执行写入、重启或配置变更前，核对本次需求授权、目标及影响；涉及旧数据迁移的 SQL 仍只提供脚本供用户手动执行。
6. 交付说明实际使用的工具、执行结果和未验证项；连接信息变化后同步更新本文。

## 常用只读检查

```bash
docker context show
docker ps --format '{{.Names}}\t{{.Image}}\t{{.Ports}}'
curl --connect-timeout 3 --max-time 5 -I http://localhost:8848/nacos/
curl --connect-timeout 3 --max-time 5 -fsS http://127.0.0.1:9000/minio/health/live
mysql -h 127.0.0.1 -P 3306 -u root -p -D grain_oil_ims -e 'SELECT DATABASE(), VERSION();'
```

上述 HTTP 和 MySQL 命令是后续检查入口，本次未执行。MySQL 使用交互输入密码；如需无人值守调用，应由本机凭据机制注入，避免将密码写入命令参数。Redis 若需认证，同样使用客户端支持的凭据机制；不在此提供未经核实的无认证命令。
