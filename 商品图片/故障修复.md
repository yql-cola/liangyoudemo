# 商品图片存储配置缺失

2026-11-07（Asia/Shanghai）。

## 原因与修复

`ProductImageService.client()` 在应用账号或密钥为空时抛出 `product-image-storage-unconfigured`。上传异常处理随后尝试删除未上传的原图和缩略图，再次触发相同异常，日志表现为两条 `product image cleanup failed ... errorType=BusinessException`。

本次只读检查发现，报错 Java 进程没有 `MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY` 环境变量或对应存储凭据命令行参数；本项目 MinIO 容器为 healthy。回归测试在缺少凭据时复现了相同清理告警。

- 上传验证图片后先初始化存储客户端；缺少凭据时直接返回原有错误，不查询和锁定商品，也不进入对象清理。
- 本机新增私有 `config/application-dev.properties`，从 `deploy/minio/.env` 读取应用凭据后写入对应 `MINIO_*` 属性；权限为 `0600`，已加入 Git 忽略。未复制管理凭据，文档不保存密钥。
- MinIO 集成测试使用 Spring 最终解析的存储配置，支持环境变量和本地属性文件。

## 生效条件

后端工作目录为项目根目录、profile 为 `dev`，且未通过 `spring.config.location` 等覆盖默认配置搜索路径时，Spring Boot 自动读取本地文件。系统环境变量可覆盖同名本地属性。重启当前后端后再上传图片；当前运行中的 Java 进程不会因磁盘文件新增而自动获得凭据。

连接入口及凭据来源见[本机开发连接与工具说明](../公共文档/本机开发连接与工具说明.md)，配置操作见[MinIO 部署说明](../deploy/minio/README.md)。本次不涉及 SQL、数据库迁移、桶策略或账号变更。

## 2026-11-08 上传后图片不回显

现象：上传完成后，列表和详情仍显示图片占位图，后端出现 `Unable to handle the Spring Security Exception because the response is already committed`，并涉及 `/error` 分发。

图片读取接口原先使用 `StreamingResponseBody`，完成输出后会触发异步分发。当前安全配置为无状态 JWT，JWT 过滤器继承 `OncePerRequestFilter`，默认不处理异步分发，而权限过滤器仍会校验请求。二次分发失去原请求认证后，可能在图片响应已经提交时触发权限异常；错误分发又会受到认证检查。新增测试确认旧实现会启动异步处理。

修复仅涉及商品主图、缩略图响应：改用 `InputStreamResource`，由 Spring MVC 在已认证的当前请求中流式输出并关闭存储输入流，避免异步二次分发。保留接口地址、图片类型、私有缓存和现有权限判断。

新增 `ProductImageHttpSecurityTest`，使用真实 Spring Security 过滤链和请求头 JWT 认证流程，模拟存储、Token 解析和 Redis；覆盖原图与缩略图完整响应、同步完成、输入流关闭、未登录 401、无权限 403、存储失败 503。回归测试先在旧实现的同步响应断言失败，修复后通过。

```sh
mvn -Djava.awt.headless=true -Dtest=ProductImageHttpSecurityTest,ProductControllerTest,ProductImageServiceTest,ResourcePermissionAuthorizationManagerTest,ResourcePermissionSecurityTest test
```

本次未修改前端、SQL、存储账号或桶策略。测试未连接真实 MinIO、Redis 和业务数据库；未重启 IDE 业务进程，浏览器实际回显需在后端重启后验证。
