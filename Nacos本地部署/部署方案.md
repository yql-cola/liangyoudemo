## 推荐方案

1. 使用单独 Compose 项目部署固定版本 `nacos/nacos-server:v2.4.3-slim`，核对实际镜像架构和启动后版本。
2. 使用 standalone 模式，继续连接现有 `ry-config` 库。容器内数据库地址调整为 `host.docker.internal`；数据库密码从现有私有配置读取到受限权限、被 Git 忽略的部署配置，不放入命令参数或本文。
3. 保持宿主机 `127.0.0.1:8848` 和客户端 gRPC `127.0.0.1:9848`；保持当前认证语义，端口限定本机访问。
4. Nacos 数据目录、日志持久化，设置日志轮转、健康检查和 restart: always。MySQL 暂未就绪时由容器失败重启重试，避免一次启动失败后永久停止。
5. macOS 用户登录时启动 Docker Desktop；MySQL 继续沿用已启用的登录启动。Docker Desktop 的自动启动发生在用户登录后，不等于尚未登录时运行。
6. 容器健康后核对配置标识与实际正文摘要、控制台、9848 端口和容器重启后的恢复。原宿主机 Nacos 只在切换时停止；原安装目录和其他项目容器保留，可用于回退。

## 备选方案

- 继续使用宿主机 Nacos，修正脚本并加 LaunchAgent：无需镜像，但不满足用户希望放入 Docker 的方向。
- Nacos 与 MySQL 同时容器化：涉及已有数据库迁移、账号授权和其他应用连接，超出本次最小变更。若选择此方案，另行给出一次性迁移 SQL 供用户手动执行，Agent 不执行迁移。

## 范围与验证限制

本方案不修改数据库结构、不执行旧数据迁移 SQL、不升级 Nacos、不改业务服务配置。不能自动重启整台电脑验证；最终记录容器重启验证与登录启动配置的检查结果，电脑重启后的验证由用户实际重启后确认。
