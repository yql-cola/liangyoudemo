# Nacos 本地操作说明

本机部署时间：2026-11-08。排查依据和边界见[部署方案](部署方案.md)，验证结果见[验收记录](验收记录.md)。

## 访问与启动

- 控制台：<http://localhost:8848/nacos/>。
- 客户端连接地址继续使用 `127.0.0.1:8848`；gRPC 使用本机 9848。
- Compose 项目：`liangyou-nacos`；容器：`liangyou-nacos-nacos-1`。
- 镜像：`nacos/nacos-server:v2.4.3-slim`，Compose 固定镜像摘要，ARM64。

原入口已转为启动 Docker 容器，可从任意工作目录执行：

```bash
/Users/yaoqianglong/Projects/本地/nacos/bin/start-nacos.sh
```

也可在本项目根目录执行：

```bash
bash deploy/nacos/start.sh
```

启动脚本等待容器健康后才报告成功；如果 Docker 尚未就绪，先打开 Docker Desktop 再重试。原生脚本备份在原目录的 `start-nacos.sh.before-docker-20261108`，原 Nacos 安装和日志均保留。

## 重启电脑后的行为

1. 登录当前 macOS 用户后，`~/Library/LaunchAgents/com.liangyou.docker-desktop.plist` 执行 `open -g -a /Applications/Docker.app`。
2. Docker Desktop 启动后，Nacos 的 `restart: always` 让容器自动运行。不要用 `docker compose down` 删除容器，否则需要先重新执行启动脚本。
3. MySQL 沿用现有 `homebrew.mxcl.mysql` 登录启动；如果数据库尚未就绪导致 Nacos 退出，Docker 按重启策略重试。

这里使用独立 LaunchAgent 实现 Docker 登录启动，没有改写运行中的 Docker Desktop 设置文件；其界面中的 AutoStart 开关可以仍为关闭。此机制在用户登录后运行，不保证在 FileVault 解锁或用户登录前提供服务。

## 日常检查

以下命令在本项目根目录执行；本机 Docker CLI 位于 `/usr/local/bin/docker`。

```bash
/usr/local/bin/docker --context desktop-linux compose -f deploy/nacos/compose.yml ps
curl -fsS http://127.0.0.1:8848/nacos/v1/console/health/readiness
/usr/local/bin/docker --context desktop-linux compose -f deploy/nacos/compose.yml logs --tail 100 nacos
```

readiness 应返回 `OK`，容器应为 `healthy`。新日志查看 Docker 容器和持久化日志卷，原安装目录日志只保留宿主机运行时的历史记录。不要将可能包含业务配置或敏感信息的完整日志粘贴到公开位置。

手动重启：

```bash
/usr/local/bin/docker --context desktop-linux compose -f deploy/nacos/compose.yml restart nacos
bash deploy/nacos/start.sh
```

手动停止到下次 Docker 引擎启动：

```bash
/usr/local/bin/docker --context desktop-linux compose -f deploy/nacos/compose.yml stop nacos
```

`always` 策略会在下次 Docker 引擎启动后重新运行已停止的容器。要长期停用，需先调整重启策略或移除该 Compose 服务；不要删除持久化卷或数据库。

## 数据与凭据

- 继续连接宿主机 MySQL `ry-config` 库，容器内地址为 `host.docker.internal:3306`。本次没有创建、升级、迁移数据库，也没有 SQL 手动执行步骤。
- `deploy/nacos/.local/application.properties` 从原 Nacos 配置生成，仅替换数据库主机名；目录权限 0700、文件权限 0600，局部 `.gitignore` 忽略整个 `.local/`。
- `deploy/nacos/.local/before-configs.json` 保存切换前 public 配置的标识（列表接口的 MD5 为 null，不能用于内容验证）；`original-native-sha256.json` 保存原生缓存计算出的实际正文摘要，与容器 API 正文逐条比对通过。这些文件不保存配置正文。
- 认证沿用原实例的关闭状态，8848/9848 仅绑定本机回环地址。此配置用于本机开发。
- 命名卷 `liangyou-nacos_nacos-data`、`liangyou-nacos_nacos-logs` 保存容器数据与日志；配置的主数据仍在原 MySQL 中。
- Docker 控制台日志限制为 10 MB × 3；应用文件日志沿用镜像 logback 的滚动配置。

如果原数据库密码或其他 Nacos 配置后续变更，需同步修改私有配置文件并重启容器。原目录配置和容器私有配置是两份文件，不自动同步。不要执行会展开凭据的配置打印或环境变量转储命令。

## 回退到原生 Nacos

先移除本次 Compose 服务以避免重启电脑后重新占用端口，保留卷和数据库：

```bash
/usr/local/bin/docker --context desktop-linux compose -f deploy/nacos/compose.yml down
cd /Users/yaoqianglong/Projects/本地/nacos/bin
cp start-nacos.sh.before-docker-20261108 start-nacos.sh
JAVA_HOME=$(/usr/libexec/java_home -v 17) bash startup.sh -m standalone
curl -fsS http://127.0.0.1:8848/nacos/v1/console/health/readiness
```

如需撤销本次 Docker 登录启动，可卸载并删除本次新增的 LaunchAgent；不影响 MySQL 原有启动项：

```bash
launchctl bootout "gui/$(id -u)/com.liangyou.docker-desktop"
rm ~/Library/LaunchAgents/com.liangyou.docker-desktop.plist
```

原生 Nacos 同样依赖 MySQL 先就绪。原生回退启动命令本次未执行，避免占用已部署容器的端口。
